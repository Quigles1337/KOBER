# ADR-0002 — Repo layout, Rust toolchain, and CI stand-in

- **Status:** accepted (Session 2, 2026-08-22)

## Context

§P0.5 scaffolds the Lean project, the Rust workspace, and "CI if the environment supports it
(discover, don't assume)". Discovered: the repo has no remote (remote creation is an open
escalation to Al, ADR-0000), so GitHub Actions cannot run; Rust 1.91.0 (rustc/cargo/clippy) is
installed via rustup.

## Choice

1. **Layout:** Lean project under `lean/` (lakefile.toml, package `kober`, lib `Kober`); Rust
   workspace rooted at `/Cargo.toml` with member crate `engine/` (`kober-engine`). Program
   registers stay under `PROGRAM/`; scholarship artifacts under `analysis/`; stored sources
   under `sources/`.
2. **Rust pin:** `rust-toolchain.toml` pins channel 1.91.0 (the installed stable). Upgrades via
   ADR, same policy as Lean.
3. **CI:** deferred until a remote exists. The stand-in gate is `scripts/check.sh` — lake build,
   cargo test, cargo clippy at `-D warnings` — which E9's "green default branch" means from now
   on. When Al approves a remote, a GitHub Actions workflow wrapping the same script becomes a
   new INFRA task (and must respect the machine's Actions-billing history: never require a
   status check that cannot run).

## Consequences

- `scripts/check.sh` is the phase-appropriate build for ORIENT (§4.1) from this commit forward.
- Edition 2024 for Rust crates; clippy runs at deny-warnings from day one so debt never
  accumulates (G2 requires it anyway).
- `.gitignore` covers `.lake/` (unanchored — the Lean build dir lives under `lean/`) and
  `/target/`.
