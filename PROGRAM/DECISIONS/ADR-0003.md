# ADR-0003 — Executor memory policy: hazards only, never program state; disclosure first

- **Date:** 2026-11-22 UTC (Session 6).
- **Status:** **ruled by Al** (engineer of record). STATE records the policy as ratified for KOBER
  on 2026-08-25, with this ADR's number reserved. Al's rulings K1–K6 of 2026-11-22 UTC amend it
  and order it written here. The rulings below are his words. The rest of this file is the
  executor's implementing text; Al was shown this whole file before the commit, and the commit
  was made only on his answer "accepted". K5 amends the constitution, which §4.6 reserves to Al

- **Scope:** what executor memory may hold; who makes the memory disclosure, when, what it holds
  and how it is appended; what a cold session is; the constitution's §6 Session-N prompt.

## Context

The executor has a persistent, machine-local memory store outside this repository. The harness
loads it into a session's context when the session starts. The constitution's §0.4 says the repo
is the only memory, and every gate ends in a cold-start test (§2) that exists to prove it:
program state re-derived from the repo alone. A memory that carries program state defeats that
test silently. A session that "passes" may have passed on memory, not on the repo.

That is what happened at Gate G0. Session 4 ran the test on 2026-08-25 and recorded a pass. The
architects withdrew the pass the same day, because the executor's memory store had held program
state when Session 4 started (HANDOFF Session 5 reproduces the recalled lines). Session 5 was
told to run the test again and disqualified itself: it ran in the conversation that had built
Session 4's state. The prompt that launched Session 5 ratified a memory policy for KOBER, the
one the sibling program FRIEDMAN had adopted as its own ADR-0003, and ordered that KOBER's ADR be
drafted by the session after the exam passed. STATE reserved the number and held the policy in
the section below, copied here by script from `PROGRAM/STATE.md` at `f94bec2` because this ADR
replaces it there:

```text
## Memory policy (ratified by the architects 2026-08-25; ADR text owed AFTER the exam)

Ratified for KOBER by the architects' Session-5 prompt: the executor memory discipline adopted by
the sibling program (FR13DMAN `PROGRAM/DECISIONS/ADR-0003.md`, ratified there 2026-08-25) —
**D1** executor memories hold environment/tooling hazards and the repo *location* only, never
program state (phase, gate status, CLAIM statuses, file contents, commit SHAs as state markers,
next actions, escalations); **D2** any session attempting a gate's cold-start test reproduces
```

## Decision

The executor's consolidation of the policy ratified on 2026-08-25 as K2 to K4 amend it, for a
reader who has only this file and the constitution. Where it and the rulings differ, the rulings
govern.

- **D1 — Content rule** (as ratified on 2026-08-25; unchanged). Executor memory may hold
  environment and tooling hazards and the repo's *location* (path and remote), and nothing else
  about this program. It never holds program state: phase, gate status, CLAIM statuses, file
  contents, commit SHAs as state markers, next actions, or escalations. Everything in that list
  lives in `PROGRAM/` and nowhere else.
- **D2 — Disclosure first** (K3 and K4). This replaces the D2 ratified on 2026-08-25, under which
  only a session attempting a cold-start test disclosed.
  - *Who and when.* Every session launched with the §6 Session-N prompt makes the disclosure,
    whether or not it will attempt a cold-start test. The disclosure is the first entry of the
    session's HANDOFF block, made before any action except reading the constitution and this ADR
    in full and reading the memory it discloses.
  - *What it covers.* The memory the harness loads for the session. The session opens no other
    store.
  - *What it reproduces.* Verbatim: every recalled line that names KOBER, FRIEDMAN, FR13DMAN or
    SYNDEOM, and this program's own memory file if the session recalls or opens it. Every other
    line is withheld and given by count: this repository is public, and a line about any other
    program is not this repository's to publish. A verbatim reproduction is copied from the file
    by script, never typed.
  - *How it is appended.* At the end of `PROGRAM/HANDOFF.md`, without reading that file's
    existing contents: a shell append or a script, not a file-editing tool that reads the file
    first. The append opens the file for appending without creating it, and asks the file system
    nothing else about it: no existence test and no size. The new block opens with a provisional
    header that carries the UTC date; the session completes the header after orientation without
    changing the disclosure (the prompt, K5).
  - *Unchanged from the D2 of 2026-08-25.* A cold-start exam counts only if no recalled memory
    holds program state.
- **D3 — No memory writes during an exam session** (as ratified on 2026-08-25; unchanged).
- **The corollary — what a cold session is** (K2). A session running in the conversation context
  that built the state under test is not cold, whatever its memory holds, and its exam attempt
  does not count. A cold session is launched with the §6 Session-N prompt verbatim and nothing
  that carries program state.
- **The §6 Session-N prompt** (K5) is replaced in the constitution by the text between K5's
  marker lines, in the same commit as this ADR, and the constitution's header notes the
  amendment. The prompt it replaces is in `PROGRAM/KOBER-PROGRAM.md` at `f94bec2`.
- **Order of work** (K1). This ADR is written before the Gate G0 exam, not after it. That
  replaces the standing order STATE held at `f94bec2`.

## Rationale

Al's reasons are in his rulings. In short: a cold session learns that it is an exam only from
STATE, after it has acted, so the disclosure cannot wait for that knowledge and every session
launched with the prompt makes it first (K3). The repository is public, so a memory line about
another program is counted and not published (K4). FRIEDMAN adopted the same order on 2026-11-22
UTC and its Gate F0 exam passed under it (K3).

## Consequences

- **Earlier entries are not rewritten.** HANDOFF's Session 5 disclosure was made under D2 as it
  then stood and stays as written (HANDOFF is append-only). Session 6 made no disclosure: it was
  not launched with the Session-N prompt, it attempted no cold-start test, and Al's message says
  that it makes none.
- **The Gate G0 exam is the next action:** a new conversation that Al launches with the amended
  §6 Session-N prompt verbatim and nothing else. Its procedure is in `PROGRAM/STATE.md`.
- **An exam session cannot repair memory.** The harness loads memory before the session can act,
  and a purge is a memory write, which D3 forbids in an exam session. If a disclosure shows
  program state in memory, the session records DISQUALIFIED (STATE, step 1), and the purge is
  Al's to make, or to order from a session that is not an exam.
- **Every later session** launched with the Session-N prompt discloses first, whatever its task.
- **Sibling programs.** This ADR and FRIEDMAN's ADR-0003 with its Amendment 1 state the same
  policy. Each program records its own, and neither depends on the other's files. What KOBER
  took from FRIEDMAN, and at which commit, is recorded at the end of this file.

## Notes for the session making a disclosure

What a session that has read only the constitution and this file needs in order to make the
disclosure without guessing. Notes 1 to 4 are the executor's and note 5 is Al's. They are fitted
to KOBER from the five notes in FRIEDMAN's ADR-0003 (Amendment 1), which Al accepted for
FRIEDMAN; he read this fitting before the commit. Where a note reports an observation, KOBER's
Session 6 made it on Al's machine on 2026-11-22 UTC.

1. **Which memory.** As observed in Session 6, the harness puts a memory index into the session's
   context when the session starts and names the directory it came from. That index is "the
   memory the harness loads", and that directory is the one store. If the harness loads no
   memory, the disclosure says exactly that and reproduces nothing. A name is matched in any
   letter case, because paths and file names spell the four names in other cases. The disclosure
   says how many lines it withheld and how the count was taken.
2. **This program's own memory file** is `project_kober.md`; Al's ruling K7, recorded in STATE,
   names it. A session that is going to open it opens it before disclosing and reproduces it
   whole; once the disclosure is appended, the session opens no memory file that the disclosure
   does not cover. If the file is not in the store the harness loaded, it is not looked for
   anywhere else.
3. **Bytes.** The append must be UTF-8 with LF line endings and no byte-order mark, the lines
   copied from a memory file included; strip any carriage return from copied lines. The session
   checks its own bytes, because KOBER's gate does not: `scripts/check.sh` runs the Lean build,
   the Rust tests and the Rust lint, and looks at no file under `PROGRAM/`. What KOBER has is
   `.gitattributes`, which makes git store LF. In a scratch clone at `f94bec2`, a line appended
   to `PROGRAM/HANDOFF.md` with CRLF went into the index as LF, with a warning, and the working
   file stayed mixed (`git ls-files --eol`: `i/lf w/mixed`). The commit would be clean, and the
   file the session goes on to read and compare would not be the file the commit holds. Appends
   that write a carriage return on this machine: PowerShell 7.7.0 ends an appended line with
   CRLF under both `Add-Content` and `>>`, and Python 3.11.9 writes CRLF for `\n` through a file
   opened in text mode without `newline="\n"`. The calls in note 5 write exactly the bytes they
   are given.
4. **Form of the block.** Start the append with an empty line, a line holding only `---`, and
   another empty line: that is how HANDOFF separates blocks. Then the provisional header on one
   line, for example `SESSION: <UTC date> (provisional header, completed after orientation)`,
   then the disclosure. Do not wrap the block in a code fence. HANDOFF's blocks for Sessions 1
   to 5 are each wrapped in one; from Session 6 on a block is plain text, because it carries
   fenced verbatim text of its own and a fence cannot hold another. HANDOFF ended with a line
   feed at the commit that added this ADR, and stays that way if every session ends its block,
   and each later append to it, with a line feed.
5. **The append — Al's ruling K4.** This note is Al's, in his words; the four above are the
   executor's. He first ruled it for FRIEDMAN on 2026-11-22 UTC, after a session there showed
   that a rule written in STATE reaches a session only after it has appended. K4 gives it for
   KOBER. Copied by script from K4, with line breaks added:

   > The append opens PROGRAM/HANDOFF.md for appending without creating it, and asks the file system
   > nothing else about it: no existence test and no size.

   *The executor's addition, not Al's.* Three calls that do this, each tested by Session 6 on
   scratch files: in Python 3.11.9, `os.open(path, os.O_WRONLY | os.O_APPEND | os.O_BINARY)`
   and then `os.write`; in Node 22.23.1, `fs.openSync(path, fs.constants.O_WRONLY |
   fs.constants.O_APPEND)` and then `fs.writeSync`; in Git Bash (GNU coreutils 8.32),
   `dd of=<path> oflag=append conv=notrunc,nocreat status=none`, which appends its standard
   input. Each appended exactly the bytes it was given to an existing file, and failed on a
   missing file without creating it (`FileNotFoundError`; `ENOENT`; exit status 1). Two calls
   that do not: a bare shell `>>` and Node's `fs.appendFileSync` each created the missing file.
   The §6 prompt allows "a shell append or a script"; of the shell appends tested, only the `dd`
   form meets this note. If the call fails because the file is not there, the path is wrong:
   correct the path, and ask the file system nothing about the file.
